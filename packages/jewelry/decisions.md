# Decisions

All decisions for this package are kept in the repository root `decisions.md`.
- **Android emulators run offline.** Added on 2026-11-10. Firebase is reached on 127.0.0.2 through `adb reverse` and the fakes through `adb forward`, so a scenario needs no network. Wi-Fi and mobile data are switched off after boot; `internet: true` on a profile keeps them and then checks the emulator really has internet. Apps that check for internet themselves must be told they are online (MedApp does this under its `JEWELRY` define).
- **The top inset is pinned to 24 dp on Android.** Added on 2026-11-10. Emulators of one AVD report either the status bar alone (72 px on a Pixel 8 Pro) or the status bar plus the camera cutout (151 px), per boot, which shifted every screen 26 frame pixels between goldens. Each scenario sets the test view's top padding and view padding to 24 dp; device screenshots are untouched.
- **The app gets a harness clock.** Added on 2026-11-11. Each scenario runs inside `withClock` (package:clock), and frame callbacks too, with a clock that starts at the device minute the scenario began and moves with pumped time plus real time spent in `t.wait`. Times the app shows no longer depend on how slow a run was. `DateTime.now()`, server timestamps and other isolates keep the device clock.
- **Emulators show a real lock screen.** Added on 2026-11-11. A wiped emulator has its lock screen switched off and lets the lock screen time out to black, so scenarios that locked the phone recorded black frames. After boot jewelry switches the (swipe) lock screen on and keeps the screen awake while plugged in. `tapNotificationAction(text, opensApp: true)` tells jewelry that a tap brought the app to the front.
- **Ignored widgets instead of looser matching.** Added on 2026-11-11. Animations on a wall-clock timer or that loop forever (MedApp's hint arrow, its pulsing step indicator) made frames differ between runs. `t.ignore(target)` and `ctx.ignore(target)` store the widget's rectangle with every frame, and comparisons blank it in that frame. Considered and dropped: matching a step's frames in any order, which fails as soon as anything else on screen changes at the same time. Each frame blanks its own rectangles, not the union with the other recording's, which holds while the widget stays in place.
- **The app's timers run on the harness clock.** Added on 2026-11-11. MedApp's pharmacy promo and its "Medicijn wekkers inplannen" banner start on wall-clock timers, so they landed on a different frame every run and failed 15 of 41 scenarios. During a scenario on a device, `Timer`, `Timer.periodic` and `Future.delayed` made by app code (including Flutter's widgets and plugins) fire when the app clock reaches them, so a popup 5 s after login appears the same number of frames after login every run. Timers from flutter_test, integration_test, jewelry, gesture recognizers and the scenario's own code under `integration_test/` stay on wall time, judged by the caller in the stack trace. When nothing pumps for a second, a due app timer fires on wall time anyway, so app code waiting on a timer cannot hang the test. Considered and dropped: a hook in MedApp per popup, which the next timer-driven popup would need again.
